1. Граждане видят **только глобальные** лоты.  
2. Стражи+ видят **локальные** и **Экспорт**.

## Канон (уже в ядре)

### Тип лота (из Свода «Доступ», без новой колонки)
- **Глобальный** — в доступе есть **Г**. Подтверждает **Агент СБ** (часто сразу `completed`). Не перемещается между городами.
- **Локальный** — только **Ст / Сд / М**. Подтверждает **живой Страж**. Остаток по городу.

### Кто что видит
| Роль | Витрина |
|------|---------|
| Гражданин | только `lot_scope=global` |
| Страж / Судья / Мэр / Айя | глобальные + локальные + **Экспорт** |

Гражданам **нельзя** показывать локальные/экспорт (даже если API отфильтрует — UI не должен предлагать фильтр «локальные»).

### Экспорт
Если в текущем городе остаток = 0, а в другом > 0 и лот ещё **не просрочен** на витрине владельца:
- `display_status: "Экспорт"`, `is_export: true`
- `owner_node_id` / `owner_city_hint`
- цена = цена Свода (`unit_svod` / `unit_buyer_price` без наценки)
- пример строки UI:

```
Лот: video_create | Цена: 50 КВАЗИ | Доступ: Ст | Статус: Экспорт (г. node-export-demo) | Осталось: 14 дн.
```

(Если API отдал `ui_line` — можно показывать его как есть.)

### Время жизни (`shelf_life` → `expires_at`)
- В Свод **не** входит.
- В ответе листинга: `expires_at` (unix), `shelf_life_secs` (осталось секунд).
- Просроченные ядро **не отдаёт** в `GET /exchange/listings`.
- Продление до истечения: `POST /exchange/listings/:id/extend` `{ "shelf_life_secs": 604800 }` — только Агент/Страж+/Айя; после истечения ошибка `Lot already expired, please re-list`.

## API (контракты)

### Витрина
```
GET /exchange/listings?node_id=<текущий_город>
GET /exchange/listings?lot_scope=global
GET /exchange/listings?lot_scope=local&node_id=...
GET /exchange/listings?affordable=true
```

Поля ответа (важные):
- `svod_code`, `unit_svod`, `unit_buyer_price`, `qty_remaining`
- `lot_scope`: `global` | `local`
- `confirm_mode`: `agent_sb` | `live_guardian`
- `is_export`, `display_status` (`"Экспорт"` / `"Локальный"` / null)
- `owner_node_id`, `owner_city_hint`, `access_short`, `ui_line`
- `expires_at`, `shelf_life_secs`
- глобальные республики: часто `is_state_agent`, `agent: "exchange"`, цена покупателя может быть **+10%**
- экспорт/локальные: цена = Свод (без +10%)

### Покупка глобального
```
POST /exchange/listings/:id/buy  { "quantity": N }
```
Глобальный: часто сразу `completed` (`confirm_mode=agent_sb`).  
Локальный: `escrowed` + `pending_sb` / живой Страж.

### Потребность → лот республики
```
POST /exchange/needs
{ "svod_code": "...", "quantity": N, "shelf_life_secs": 2592000 }  // опционально
```

### Остатки города (Страж+)
```
GET  /exchange/node-lots?node_id=...
POST /exchange/node-lots
{ "node_id": "...", "svod_code": "video_create", "quantity": 3, "shelf_life_secs": 2592000 }
```

### Экспорт — 9 шагов
```
POST /exchange/exports
{ "svod_code": "video_create", "from_node_id": "<владелец>", "to_node_id": "<наш город>", "quantity": 1 }
# или listing_id вида export:owner:code

POST /exchange/exports/:id/advance  { "step": 2 }  // … до 9
```
Шаги: 1 open → 2 buyer SB → 3 owner SB → 4 reserve → 5 call guardian → 6 transfer → 7 listed buyer → 8 receipt → 9 completed.

Алиасы: `/exchange/transfers` те же.

### Продление
```
POST /exchange/listings/:id/extend  { "shelf_life_secs": 604800 }
```

### СБ-очередь (Страж+)
```
GET  /exchange/security/tasks
POST /exchange/security/tasks/:id/confirm
```
Глобальные с `agent_sb` повторно подтверждать не нужно.

## Что сделать в Flutter

### 1. Биржа — сегментация по роли
- Если роль < Страж: только глобальные лоты; скрыть вкладки «Локальные / Экспорт».
- Если Страж+: три блока или фильтр: **Глобальные | Локальные | Экспорт** (`is_export`).
- Передавать `node_id` текущего города/узла пользователя в `GET /exchange/listings`.

### 2. Карточка/строка лота
Показывать минимум:
- код/название, цена (КВАЗИ), доступ (`access_short` или из Свода),
- бейдж **Экспорт** / **Локальный** / без бейджа для глобального,
- для экспорта — город-владелец,
- **«Осталось: N дн.»** из `shelf_life_secs` (или готовый `ui_line`).

Не рисовать +10% для экспортных/локальных (брать `unit_buyer_price` как пришло; для экспорта это цена Свода).

### 3. Покупка
- Глобальный: привычный buy; учесть авто-complete Агентом СБ (не всегда ждать ручного СБ).
- Локальный: buy → статус ожидания живого Стража.
- Экспорт: **не** обычный buy — экран мастера **9 шагов** (`/exchange/exports` + advance), статусы на русском по шагам.

### 4. Страж+: инструменты
- Очередь СБ (как раньше).
- Управление остатком города (`node-lots`) + опционально `shelf_life_secs` при выставлении.
- Кнопка «Продлить» на активном лоте (`extend`) — только до истечения; после — «выставить заново».

### 5. Потребность / Агент Биржи
При создании need можно слать `shelf_life_secs` (или дефолт на сервере 30 дней). В UI после создания показать `expires_at`.

### 6. Не делать
- Не менять Свод в приложении под `shelf_life`.
- Не показывать гражданам локальные/экспорт.
- Не продлевать после expire (сервер откажет — показать текст ошибки).
