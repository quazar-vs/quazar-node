## Канон API

### Свод
- `GET /svod` → **`lots`** / `items` — **один** список лотов (не две части Разработка/Реализация).
- Поля лота: `code`, `base_price`, `lot_scope`, `access` / `access_roles`, `access_level`.
- `parts` — legacy; не строить UI на двух частях.

### Витрина
- `GET /exchange/listings?node_id=...`
- Только лоты с **госостатком > 0** (+ фильтр по роли на сервере).
- Гражданин: только доступные по Г / его статусу.
- Страж+: local + строки **`display_status: "Экспорт"`** — **без города** в подписи (`ui_line`: «Статус: Экспорт»).

### Заявка
1. Витрина → выбрать лот → подать заявку (`POST /exchange/needs` для снабжения/секретаря; сделка с витрины — buy/application).
2. Секретарь через needs выставляет **только global**.
3. СБ: если роль соответствует `access_level` — авто; иначе очередь; Страж не confirm’ит судьино, Судья может confirm’ить стражево.

### Не делать
- Не показывать две части Свода.
- Не писать город в статусе Экспорт.
- Не ждать «живой СБ» для авто-принятых заявок.
- КВАЗИ / +10% не менять в приложении.
